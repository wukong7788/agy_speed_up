# Antigravity Config, Sandbox & Permission Files

## 1. Where Settings & Permission Grants Are Stored

You do not need to configure every option through the UI manually; Antigravity stores settings in JSON files on disk:

- **Global App config**: `~/.gemini/config/config.json`
  - Protected by Antigravity's hardcoded system protection boundary (`App v2.35.0+` also keeps sensitive configuration directories and internal session files protected even in Auto mode): an AI agent cannot read or edit this file directly; edit it yourself in a terminal/editor or sync it across machines with dotfiles.
- **CLI settings**: `~/.gemini/antigravity-cli/settings.json`
  - In `CLI v1.5.15+`, `AGY_CLI_AUTO_COMPACT_OVERRIDE` (accepting a token count like `700000`, `K`/`M` shorthand like `800K`, or percentage like `80%`) sets native auto-compaction thresholds across eligible models, visible under `/context`.
- **Per-project overrides**: `~/.gemini/config/projects/<project-id>.json`
  - Can be inspected/synced across machines by the user directly (note: agents should not modify their own permission/sandbox policy state files; configure grants in UI Settings or edit the JSON yourself after checking the live v2 schema generated by the app).
  - Example observed structure:
    ```json
    {
      "id": "<project-uuid>",
      "name": "stock_notify",
      "projectResources": {
        "resources": [
          {
            "gitFolder": {
              "folderUri": "file:///path/to/repo"
            }
          }
        ]
      },
      "permissionGrants": {
        "v2Migrated": true
      },
      "settings": {
        "fileAccessPolicy": "AGENT_SETTING_POLICY_ASK",
        "sandboxMode": true,
        "autoExecutionPolicy": "CASCADE_COMMANDS_AUTO_EXECUTION_AUTO",
        "permissionPreset": "AGENT_PERMISSION_PRESET_AUTO"
      },
      "isWorkspaceOnly": false
    }
    ```
  - Common observed `settings` values across projects:
    - `fileAccessPolicy`: `AGENT_SETTING_POLICY_ASK` | `AGENT_SETTING_POLICY_ALLOW`
    - `internetPolicy`: `AGENT_SETTING_POLICY_ASK`
    - `autoExecutionPolicy`: `CASCADE_COMMANDS_AUTO_EXECUTION_AUTO` | `CASCADE_COMMANDS_AUTO_EXECUTION_PROCEED_IN_SANDBOX`
    - `artifactReviewMode`: `ARTIFACT_REVIEW_MODE_TURBO`
    - `sandboxMode`: `true` | `false`

### Safe Workflow for Modifying Project Configs (External Agent / Script)

1. **Locate the matching project file** without guessing UUIDs:
   ```bash
   python3 -B ./scripts/configure-project-permissions.py --project-dir /path/to/repo --show
   ```
2. **Capture a verified `permissionGrants` template once**:
   - Antigravity v2 project configs mark migration with `"permissionGrants": { "v2Migrated": true }`. Do not invent undocumented `permissionGrants` field names blindly.
   - Add your desired rule once in the UI (e.g. `read_file` for `/var/db/xcode_select_link`, or `Always Allow` on `rtk git push origin main`), then inspect the updated `~/.gemini/config/projects/<project-id>.json` with `--show`.
3. **Preview and replicate across repos/machines**:
   - Dry-run first (no `--apply`), then run with `--apply` (which saves `<project-id>.json.bak` first):
     ```bash
     python3 -B ./scripts/configure-project-permissions.py \
       --project-dir /path/to/repo \
       --preset auto \
       --copy-grants-from ~/.gemini/config/projects/<golden-id>.json \
       --apply
     ```

## 2. Sandbox Mounts & Network Rules (Official Docs Summary)

Per `https://antigravity.google/docs/sandbox` and `https://antigravity.google/docs/permissions`:

- Rule precedence is strictly **Deny > Ask > Allow**.
- `read_file(...)` permission rules extend read-only mounts inside the sandbox; `write_file(...)` rules extend read-write mounts.
- `read_url(...)` rules populate the outbound sandbox network allowlist.

## 3. Keeping Unsandboxed Commands Auto-Approvable

When a command truly needs `BypassSandbox: true` (e.g. `git push`, external network requests, loopback port binding tests), keep its shell form prefix-matchable so "Always Allow" does not re-prompt on every invocation.

Per `https://antigravity.google/docs/permissions`:
- **Still prefix-match normally**: pipelines, `&&`/`||`/`;` chains, quoted literals, plain `$VAR` arguments, simple file redirects, and transparent wrappers (`timeout`, `nohup`, `nice`, `env`, whose inner command is evaluated on its own).
- **Disable prefix matching** (requiring an exact character-for-character match or a `regex:` rule):
  - Command or process substitution (`$(...)`, backticks, `<(...)`) and arithmetic contexts (`$((...))`).
  - Brace expansion (`{a,b}`) and non-literal command names.
  - Network or file-descriptor redirections, and subcommand-executing tool flags (e.g. `git -c core.pager=<cmd>`, `tar --to-command`).
- Split chains (`&&`, `;`) so only the single command needing `BypassSandbox: true` runs outside the sandbox.
